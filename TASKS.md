- [ ] Model `blocked` and `blocked-by` in the git-native backend (@devin)
  - **ID**: git-native-model-blocked-by
  - **Tags**: git-native, backend, blocked-by, spec-completeness, conformance, dogfood
  - **Details**: `blocked-by` is a G6 core portable field, but the git-native backend deliberately deferred it in v1 (conformance `blockedBy: false`; `migrate` carries only title/priority/tags/details). That gap blocks a clean dogfood flip: this repo's queue has blocked tasks (`npm-release-publishing-blocker`, `set-up-github-pages-custom-domain`) that would become pickable and lose their reason text on conversion — and every blocked-task repo migrated later hits the same. Model it: add `blocked` (free-form reason) + `blockedBy` (task-id list) to the git-native `created`/`updated` event payloads, the fold, and `BackendTask`; `next()`/`pick` skip a task whose `blocked` is set or whose `blockedBy` still references an open task; `claim()` returns `blocked` for such a task; `renderGitNativeSnapshot` emits `**Blocked**:` / `**Blocked by**:`; `migrate` preserves both from the parsed task; flip the conformance git-native target's `blockedBy` capability to true and pass `blocked-by-unclaimable`. Surfaced while executing `dogfood-git-native-self-host` (user-directed clean path, 2026-06-02).
  - **Files**: `packages/cli/src/backend/git-native.ts`, `packages/cli/src/backend/types.ts`, `packages/cli/src/commands/migrate.ts`, `packages/cli/src/backend/git-native.conformance.test.ts`, `packages/cli/src/backend/git-native.test.ts`, `spec.md`
  - **Acceptance**: a git-native task with `**Blocked**` or an open `**Blocked by**` is not returned by `tasks next` and `claim` returns `blocked`; once the blocker is completed/cancelled the task becomes pickable; `renderGitNativeSnapshot` round-trips `**Blocked**`/`**Blocked by**` so the generated `TASKS.md` lints; `migrate` preserves both fields; the git-native conformance suite passes with `blockedBy: true` (12 properties); `npm run build && npm test` pass.
